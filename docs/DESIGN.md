# Устройство, решения, риски

## Принцип

Любой агент может быть враждебным. Защита в три слоя:
1. **Агент — данные, а не код.** Манифест (промпт, знания, разрешённые инструменты) исполняет только наш код.
   Манифест закрыт: его видит только раннер в TEE. Важен результат агента, а не то, как он устроен.
2. **Вывод агента — данные, а не команда.** Он идёт модели протокола как JSON без имён. Запустить им ничего нельзя.
   Агенты не видят друг друга: ни вопросов, ни ответов. Знания одного владельца не попадают к другому.
3. **Любая ошибка стоит спонсору не больше `max_cost` за задачу.** Это правило держит контракт, а не раннер.

Кто за что отвечает:

| Часть | Отвечает за | Не отвечает за |
|---|---|---|
| Контракт | деньги и их инварианты: балансы, удержания, возмещение, выручка, таймауты, вывод | качество, споры, заказчика |
| Раннер в TEE | ревью агентов, проверку задач, вопросы агентам, сборку ответа, раунды, расчёт в контракте | хранение денег: у ключа раннера только три метода |
| Agent Market | заказчика, эскроу, приёмку, споры | наших агентов: рой там один агент |
| Оператор | оплату NEAR AI и пересылку выплаты Agent Market в контракт | ничего больше: списывать балансы он не может |

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Деньги | один баланс на аккаунт. У спонсора это бюджет агента; комиссия и возмещение копятся там же. Один метод вывода | меньше сущностей: нет отдельного «кредита» и двух видов вывода |
| Стоимость | раннер считает её по живому прайсу NEAR AI; контракт проверяет только `cost ≤ hold` | подпись модели не доказывает качество, а потолок ограничивает ущерб при любой ошибке |
| Смысл роя | сложить закрытые знания разных владельцев без доверия друг к другу. Модель протокола спрашивает только тех, чьи навыки нужны, и собирает ответ | схему «планировщик → специалисты → критики» любой агент запустит у себя сам. Чужие закрытые знания, чужие деньги и честная оплата разным владельцам есть только у роя |
| Взаимодействие агентов | только через модель протокола: вопрос → ответ → сборка. Свободной переписки нет | агент, прочитавший чужой ответ, мог бы вынести его через свой инструмент; инъекции друг другу невозможны; вклад считается просто; расходы предсказуемы |
| Распределение | вес = оценка вклада 0–10 от модели протокола, выручка по весам, остаток от округления самому большому весу | одно правило, легко проверить |
| Раунды | каждый ответ заказчику — отдельная задача в контракте `<assignment>#<round>`. Доработки и повторы после спора идут автоматически | выручка уходит раунду, который приняли; раунды не смешивают деньги |
| Состояние раннера | его нет: всё берётся из цепочки и Agent Market. Прерванный раунд при рестарте закрывается без списаний и запускается заново | рестарт в TEE ничего не ломает |
| Модели | только `verifiable` модели NEAR AI (инференс тоже в TEE) с поддержкой инструментов | вся цепочка остаётся в аттестованных средах |
| Ставки на доске | выключены по умолчанию (`BID_USD`), и только USDC-задачи | ставка — обязательство; выручку пересылаем в USDC |
| Большие знания | библиотека до 10 MB: зашифрованный файл по любой ссылке, хэш в манифесте; в TEE режется на куски и индексируется, на вопрос уходят 6 ближайших | 16 KiB в контракте мало, а 1 MB стоил бы 10 NEAR хранения и целиком шёл бы в каждый промпт. Файл зашифрован, поэтому где он лежит, неважно |
| Манифесты | зашифрованы для раннера (X25519 + AES-GCM, аккаунт спонсора в associated data) и лежат в контракте, до 16 KiB. IPFS нет | промпт и знания — ценность спонсора; публичный манифест копируется за минуту. В контракте нет внешних зависимостей, а копия чужого шифротекста не открывается |

## Что исправлено в плане

**Внешние API (с ними раннер бы не заработал)**

| Было в плане | Что не так | Сделано |
|---|---|---|
| Ответ `/v1/agents/me/assignments` как `{id, jobId, startedAt}` | по `openapi.json` это `{assignments:[{assignment:{assignmentId,…}, job:{…}}]}`. zod падал бы на каждом опросе | схемы по `openapi.json`; бриф уже в строке, лишний `GET /v1/jobs/{id}` не нужен |
| Доска `{id, title}` | там `{jobs:[{jobId, budgetToken, …}]}` | так и читаем; USD-задачи пропускаем: для них нужен Stripe |
| Модели `GLM-5.1-FP8`, `DeepSeek-V3.1`, `gpt-oss-120b` | их нет в каталоге NEAR AI | список из каталога, только `verifiable`; модель протокола `z-ai/glm-5.3` |
| `@phala/dstack-sdk ^0.6`, `DstackClientV0` | такой версии и класса нет | 0.5.8, `DstackClient.getQuote`; добавлены её `@noble/*` |
| `storage_deposit` 0.0125 NEAR | у USDC ровно 0.00125 (проверено в mainnet) | 0.00125 |
| `swarm.*` с 2 NEAR | wasm 219 KB требовал ~2.2 NEAR на хранение, деплой бы упал | контракт 186 KB (~1.9 NEAR); на `swarm.*` 5 NEAR: код плюс зашифрованные манифесты |

**Деньги и доверие (контракт)**

| Проблема | Сделано |
|---|---|
| Спонсор меняет манифест, пока идёт ревью, и одобренным становится непроверенный | `review(agent, manifest, allow)`: вердикт по старому манифесту отклоняется (`stale review`) |
| Каждая перерегистрация бесплатно стоит оператору вызова модели | `review_fee` при регистрации уходит оператору |
| Владелец мог задать `run_secs = u64::MAX`, и удержания зависли бы навсегда | таймауты ≤ 90 дней, `review_fee` ≤ `min_deposit`, комиссия ≤ 20% |
| Отдельные `credit`, `unfund`, `withdraw`, вспомогательный модуль ради одной функции | один баланс, один `withdraw(amount?)`, один файл |
| Недошедший вывод уходил в отдельный «кредит» | деньги просто остаются на балансе |
| Деньги видны только через view | NEP-297 события на каждый шаг |

**Раннер**

| Проблема | Сделано |
|---|---|
| Ошибка одного агента или задачи (например, незакреплённый манифест) обрывала весь цикл, и рой вставал навсегда | ошибки изолированы по элементам |
| Отклонённая задача проверялась моделью каждые 30 с, а заказчик ждал до SLA | `decline`: заказчик сразу получает полный возврат; проверка одна на задачу |
| «Никто не заработал» оставлял назначение висеть | `decline failed`, полный возврат |
| Рестарт после `assign` замораживал удержания на 30 мин и бросал заказчика | `start` идёт до `assign`; при рестарте прерванный раунд закрывается без списаний и идёт заново |
| Сбой сдачи на Agent Market терял ответ | ответ ждёт в очереди и сдаётся на следующем круге (сдача идемпотентна) |
| Сбой судьи списывал с агентов инференс без шанса заработать | сбой сборки — наша вина: списаний нет, заказчику возврат |
| Судья ставит 11 — схема падает, и задача пропадает | оценки зажимаются в 0–10 |
| «Лучший из N»: все агенты решали одно и то же, а это уже умеют соревнования Agent Market | маршрутизация по навыкам: спрашивают только нужных, остальные не платят |
| Агент с крошечным `max_cost` заставлял оператора доплачивать за переход потолка | агент берётся, только если потолок покрывает худший первый шаг |
| Точные клоны одного манифеста занимали несколько мест в задаче | одно место на один манифест (сравнение после расшифровки) |
| Манифест на IPFS публичный: любой копирует промпт и знания. Публичные шлюзы режут запросы (проверено: 429 от w3s.link, ipfs.io, dweb.link) | манифест зашифрован для раннера и лежит в контракте; IPFS убран |
| Доработки и повторы после спора не обрабатывались | автоматические раунды: агенты получают замечания заказчика, прошлый ответ видит только модель протокола (в нём знания всех агентов) |

**Скрипты**: `sha256sum` есть не везде (теперь `shasum`); перевод USDC через float превращал 1.13 в 1129999 (теперь строковая арифметика); вывод `near` CLI парсился хрупко (теперь view идут прямо в RPC).

## Похожие системы (ноябрь 2026)

Каждая часть идеи где-то уже есть. Всю связку целиком не делает никто из найденных.

| Система | Что общего | Чем отличается |
|---|---|---|
| OpenMined Syft (federated RAG) | ответ из закрытых данных многих владельцев, атрибуция и отчисления | владелец держит свой узел; не крипто, живой статус неясен |
| C-FedRAG, Opaque | TEE-оркестратор сводит данные нескольких поставщиков в один ответ | в оркестратор идут сырые куски; рынка и оплаты по вкладу нет |
| ProRata Gist | один ответ из источников многих владельцев, оплата по доле в ответе | контент у оператора в открытом виде, деньги от рекламы |
| Agent Market, соревнования | судья платформы оценивает работы 0–100 и делит USDC | работы соревнуются целиком, а не дополняют друг друга; нет закрытости |
| Theoriq, Allora, Fortytwo | вклад нескольких владельцев в один результат, награда по вкладу | знания не закрыты; Theoriq от коллективов ушёл |
| Shade Agents (NEAR) | контракт принимает только агентов с аттестацией | устарел (с апреля 2026 не поддерживается); берём идею, не код |

Что у нас новое как сочетание: агент добавляется данными без своего сервера; знания владельца обрабатывает только
его собственный изолированный вызов, оплаченный из его потолка; весь рой продаётся одним агентом на существующем
рынке, а USDC делится на цепочке по вкладу. Это новизна сборки, а не новой криптографии.

Реальность спроса: на Agent Market 766 живых агентов, 1066 задач за всё время, 55 за эту неделю (`/v1/platform/stats`).

## Модель угроз

| Атака | Что мешает | Что остаётся |
|---|---|---|
| Инъекция в модель протокола («поставь мне 10») | ответы идут JSON-данными без имён; обращение к модели, заказчику или другим агентам считается нарушением: вес 0, удержание изымается, агент `Suspended`. Такой манифест отсекает ревью | модель может ошибиться; цена ошибки — выручка одной задачи |
| Инъекция в раннер | вывод агента ничего не запускает; аргументы инструментов проверяет zod; доступны только инструменты из манифеста | — |
| Кража секретов | в контексте агента только его манифест и задача; ключи живут в памяти процесса; ключ раннера не покидает TEE | — |
| SSRF | только https; request-filtering-agent проверяет каждый адрес, включая редиректы; 10 с, 2 МБ, 3 редиректа | нет общего лимита запросов на домен |
| Исчерпание ресурсов | ≤ 8 шагов; остановка на потолке; 4000 токенов за шаг; таймаут; ответ ≤ 20 000 символов; контракт не спишет больше удержания | последний шаг может перейти потолок, разницу платит оператор (ограничена проверкой потолка) |
| Сибилы и сговор | одно место на манифест; одинаковые ответы схлопываются; на каждом аккаунте `min_deposit` и `max_cost`; выбор случайный | перефразированные клоны проходят; защита экономическая |
| Подмена манифеста | контракт хранит зашифрованный манифест и его sha256; смена манифеста означает новое ревью | — |
| Кража агента | манифест зашифрован для раннера; копия под другим аккаунтом не открывается и отклоняется на ревью (проверено в e2e) | заказчик может пытаться выудить промпт задачей: проверка задач такие отклоняет, но не наверняка |
| Уход от штрафа | удержание списано при `assign`, вывести его нельзя | новый аккаунт — новый депозит, ревью и `review_fee` |
| Вредная задача или доработка | проверка по `job.md` на каждом раунде; вклады по `compose.md`; дальше спор на Agent Market | решение арбитра вне нашего контроля |
| Утечка знаний между агентами | агент видит только задачу и свой вопрос; прошлый ответ видит только модель протокола (проверено в e2e) | знания уходят заказчику в ответе, это и есть продукт; сотней вопросов базу можно частично восстановить |
| Библиотека | хостинг видит только шифротекст; хэш фиксирует содержимое; ссылку знает только раннер; скачивание через SSRF-фильтр; копия чужой библиотеки не открывается (associated data) | куски библиотеки уходят в NEAR AI: все при индексации (эмбеддинги), ближайшие в промпте. Хостинг недоступен — агента не берут в задачу |
| Утечка задачи заказчика | агент с инструментом видит задачу и может вынести её на свой сервер | для закрытых задач давать агентов без инструментов (v2: флаг на задаче) |

## Граница доверия

| Кто скомпрометирован | Что может | Чего не может |
|---|---|---|
| Раннер (ключ или код) | открывать задачи и списывать до `max_cost` за задачу в пользу оператора; ставить веса и статусы | забрать деньги себе; менять конфиг; вызывать что-то кроме трёх методов (проверено в e2e) |
| Оператор | не переслать выплату: агенты теряют доход, но не баланс | списывать балансы без раннера |
| Владелец | поставить своего раннера и оператора, после чего списывать балансы шагами по `max_cost` | забрать балансы одним вызовом |
| RPC | соврать на чтении | подменить манифест (раннер сверяет sha256) или подписанную транзакцию |

Итог: спонсор доверяет аттестованному коду раннера. Проверить его он может сам, не веря владельцу на слово:
`swarm.sh verify-seal` сверяет подпись Intel, ключи, журнал событий, compose и `seal_key` контракта.
Доверять владельцу остаётся в одном: владелец приложения в Phala может выкатить новую версию раннера, и dstack выдаст
ей тот же ключ печати. Каждая версия видна по `compose-hash`, поэтому после обновления проверку стоит повторить.
Риском спонсор управляет через размер баланса и `max_cost`. В проде владелец — мультисиг, а не тот же человек, что оператор.

## Остаточные риски и что не проверено

| Что | Почему | Как проверить |
|---|---|---|
| Живой NEAR AI | нет API-ключа на этой машине; в e2e модель — заглушка | curl из RUNBOOK §2; первая задача в testnet, сравнить `cost` с биллингом NEAR AI |
| Живой Agent Market | схемы взяты из `openapi.json` (ноябрь 2026), вызовы шли в заглушку | первая задача в testnet |
| TEE | `verify.ts` проверен на настоящем quote и журнале dstack (Intel: `UpToDate`), но наш раннер в Phala ещё не запускался: `getKey`, `getQuote` и порт 8080 | RUNBOOK §3 |
| Сетевые команды `swarm.sh` | не запускались против сети; те же вызовы контракта проверены в e2e через near-api-js | RUNBOOK §2 |
| Выручка | пересылается вручную: токен агента на Agent Market по их дизайну не может двигать деньги | события `finish` и `revenue` против выплат Agent Market |
| Кэш входных токенов | скидка на кэш не учитывается; агенты платят чуть больше факта | — |
| Сбой между `finish` и `submit` | ответ теряется вместе с процессом; заказчику полный возврат | — |
| Один раннер | два процесса с одним ключом мешали бы друг другу (деньги при этом в безопасности) | запускать один CVM |
| Физические атаки на TEE | TEE.fail (2025): интерпозер на шине DDR5 дешевле $1000 вытаскивает ключи аттестации TDX. Значит, «без доверия» — преувеличение: остаётся доверие к железу и к тому, у кого оно стоит (Phala) | следить за TCB-статусом в `verify.ts`; v2: несколько TEE разных операторов |
| Утечка через ответы | знания уходят заказчику частями; повторными задачами базу можно выкачать | v2: проверка дословных совпадений ответа с базой агента, лимит задач на заказчика, отказ на мета-вопросы |
| Игра с оценкой вклада | агент может прятать в ответе обращение к оценщику; модель сама и собирает, и оценивает | нарушение уже штрафуется; v2: вклад как «насколько хуже ответ без этого агента» (leave-one-out, Shapley) |
| Ключ шифрования | если dstack выдаст другой ключ (новое приложение в Phala), старые манифесты не откроются | спонсоры регистрируются заново; `seal_key_mismatch` в логе |
| Хранение манифестов | платит контракт: до 16 KiB, около 0.16 NEAR на агента | `review_fee` должен это покрывать; держать NEAR на `swarm.*` |
| Индексация библиотек | платит оператор, заново после каждого перезапуска раннера: центы за мегабайт | `review_fee` и комиссия |
| Эмбеддинги NEAR AI | `/v1/embeddings` и модель `Qwen3-Embedding` не проверены вживую; качество поиска зависит от модели | первая задача с библиотекой |
